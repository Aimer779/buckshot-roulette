# 🎰 Buckshot Roulette 恶魔轮盘（网页版）

一个基于 React + TypeScript + Vite 构建的《恶魔轮盘》（Buckshot Roulette）网页版游戏。

玩家将与 AI 庄家在 1998 年的地下夜总会里进行一场生死对决：实弹与空包弹被随机装入霰弹枪，你需要利用道具、推理与运气，在三轮对决中活下来。

🔗 **在线体验**：https://aimer779.github.io/buckshot-roulette/ *(如已部署)*  
📦 **GitHub 仓库**：https://github.com/Aimer779/buckshot-roulette

---

## ✨ 游戏特性

- **经典三轮对决**：教学局 → 道具局 → 决胜局，难度与策略逐步升级
- **实弹 / 空包弹机制**：每轮随机装填，明确显示数量但顺序未知
- **9 种核心道具**：放大镜、手铐、香烟、啤酒、手锯、肾上腺素、过期药品、逆变器、一次性手机
- **智能 AI 对手**：根据桌面可见信息决策，会使用道具，公平对战
- **双人联机**：创建密码房间，朋友凭六位房号和密码加入，三局两胜
- **暗黑视觉风格**：地下夜总会氛围，像素风 UI 与金属质感
- **音效反馈**：射击、上膛、道具使用等关键动作带有音效

## 🎮 核心玩法

| 动作 | 实弹 (Live) | 空包弹 (Blank) |
|------|-------------|----------------|
| 对自己射击 | 自己扣 1 血，回合交换 | 无事发生，**额外一回合** |
| 对对手射击 | 对手扣血，回合交换 | 无事发生，回合交换 |

### 回合配置

| 回合 | 生命 | 每轮道具数 | 特殊机制 |
|------|------|-----------|----------|
| 第一回合 | 2 格 | 0 | 无道具教学 |
| 第二回合 | 4 格 | 2 | 引入道具系统 |
| 第三回合 | 5+ 格 | 4 | 闸刀机制：低血量时无法回血 |

### 道具说明

- **放大镜** 🔍：查看当前枪膛内子弹类型
- **手铐** ⛓️：跳过对手下一回合
- **香烟** 🚬：恢复 1 点生命
- **啤酒** 🍺：弹出当前子弹（不发射）
- **手锯** 🪚：下一发实弹伤害翻倍（2 点）
- **肾上腺素** 💉：偷取对手一个道具并立即使用
- **过期药品** 💊：50% 恢复 2 血 / 50% 扣 1 血
- **逆变器** 🔄：切换当前子弹类型（实弹 ↔ 空包弹）
- **一次性手机** 📱：告知枪内某随机位置子弹类型

## 🛠 技术栈

- **框架**：React 19 + TypeScript
- **构建工具**：Vite 7
- **样式**：Tailwind CSS 3 + shadcn/ui 组件库
- **状态管理**：Zustand
- **路由**：React Router 7
- **动画**：Framer Motion / GSAP
- **音效**：Howler.js
- **包管理器**：pnpm

## 🚀 本地运行

> 需要 Node.js 20+ 和 pnpm

```bash
# 进入项目目录
cd buckshot-roulette/app

# 安装依赖
pnpm install

# 启动开发服务器
pnpm dev
```

开发服务器默认运行在 http://localhost:3000/，同时提供联机房间 API。修改 `server/` 或其复用的游戏规则后，需要重启开发服务，现有房间会随之清空。

如果本机用 pnpm 11 运行旧版 pnpm 已安装的依赖时，遇到自动重装检查或 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`，可用 `pnpm --config.verifyDepsBeforeRun=false run dev` 复用当前依赖；同样的参数也可用于 `build`、`test`、`lint`。

### 双人联机

1. 打开主菜单的「双人联机」，填写昵称和 4–64 字密码，创建房间。
2. 把六位房号和密码发给朋友。朋友访问同一个游戏服务地址，选择「加入房间」。
3. 两人点击「准备」，房主点击「开始对战」。每间房最多两人。
4. 三局两胜，每局轮换先手，生命值依次为 2 / 4 / 6；每次装弹补充道具，背包最多 8 个。每局结束后双方确认继续。
5. 放大镜和手机情报仅使用者可见。刷新当前标签页可恢复座位；离线超过 15 秒暂停对方操作，重连后继续。点击「退出并关闭房间」会关闭双方的房间。

同一局域网内运行 `pnpm dev --host 0.0.0.0`，两台设备访问 `http://房主电脑的局域网IP:3000/`。跨网络游戏需要把下面的 Node 服务部署到双方都能访问的服务器。

房间保存在单个服务进程内，双方都停止访问超过 30 分钟后失效，服务重启会清空房间。重连凭证按浏览器标签页保存，关闭标签页后无法凭密码接管已经占用的座位。

### 构建生产版本

```bash
pnpm build
pnpm start
```

构建产物为 `app/dist/`（前端）和 `app/server-dist/`（服务端）。`pnpm start` 或 `pnpm preview` 从同一个 Node 服务提供页面与联机 API，默认监听 `0.0.0.0:3000`，可通过 `HOST`、`PORT` 环境变量修改。

部署时保留 `app/package.json`、生产依赖、`dist/` 和 `server-dist/`。公网使用 HTTPS 反向代理，将页面和 `/api/` 转发到同一个服务实例并保留 `Host` 请求头。只发布 `dist/` 到静态托管（例如 GitHub Pages）可运行单机，不能提供联机房间。

联机通过浏览器原生 `fetch` 提交操作并每 800 毫秒同步一次状态；服务端校验房间凭证、回合和状态版本，未揭示的子弹队列不会发送给浏览器。房间密码采用随机盐和 scrypt 派生后保存，创建/加入接口限制每个来源地址每分钟 20 次尝试。

### 验证

```bash
pnpm test
pnpm lint
pnpm build
```

`app/server/__tests__/` 覆盖密码与容量校验、并发加入、刷新重连、操作版本校验、双方道具规则，以及两个 HTTP 客户端完成比赛和再来一场的流程。
